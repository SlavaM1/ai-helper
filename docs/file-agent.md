## Просмотр и применение

1. Проверьте фактически прочитанные файлы, завершённые операции, итоговый текст и validation diagnostics.
2. **View Diff** показывает реальные изменения; выбор файла открывает его diff. **Open File** читает безопасный numbered preview.
3. **Apply Changes** требует отдельного подтверждения с base SHA, SHA-256 артефакта и списком файлов. В Docker исходник read-only, поэтому сервер откажет с инструкцией. Это не ошибка изоляции и не успешное применение.
4. В доверенном host backend можно явно задать `AI_HELPER_FILE_AGENT_ALLOW_SOURCE_APPLY=true`. Проверяются сохранённый patch, финальная валидация, HEAD, index, content hashes и modes затронутых файлов. Посторонние изменения не перезаписываются; при конфликте автоматического retry нет.
5. Публикация предварительно staging-ит все файлы, затем выполняет CAS-проверки и rollback при ошибке. При внешних конкурентных правках безопасный rollback может быть невозможен: сервер явно сообщает **Partial source apply**, блокирует дальнейший apply и требует ручной проверки. Редактор, не соблюдающий lock, нельзя считать транзакционным участником.
6. **Discard Changes** удаляет только принадлежащую задаче копию, не исходник и не чужие worktrees. Приватные patch/base artifacts сохраняются.

HTTP `/patch` — **redacted preview**, иногда усечённый, не точный apply artifact. Точный patch, after-payload, контрольные суммы, Git bundle и shallow boundary находятся в приватном `AI_HELPER_FILE_AGENT_STORAGE/.file-agent-owners/`. Они могут содержать исходные чувствительные данные: не публикуйте их, ограничивайте доступ к volume. Для ручного переноса администратор копирует конкретный artifact из volume, проверяет SHA-256, base и `git apply --check`; применение — отдельное осознанное действие. Не применяйте redacted preview.

## Остановка и удаление из истории

- **Остановить** отменяет выбранную задачу, включая задачу в очереди. Сначала отображается «Останавливается», затем «Остановлена». Новые вызовы DeepSeek не выполняются; уже начавшийся удалённый запрос мог потребить токены до отмены.
- Текущая файловая операция безопасно завершается; частичные файлы остаются в workspace, patch сохраняется по возможности. Незавершённые изменения не считаются проверенными и не допускаются к Apply. Re-run Task создаёт новый запуск без флага отмены.
- **Удалить из истории** доступно после завершения/остановки и требует подтверждения. Запись исчезает из списка, её публичные API возвращают 404. Это логическое удаление: служебная запись SQLite и приватные snapshots сохраняются для связанных rerun/replay. Исходный проект, workspace и применённые ранее изменения не удаляются. Чтобы удалить рабочую копию, сначала используйте Discard Changes.
- API: `POST /api/file-agent/tasks/{id}/stop` с `{}` → 202; `DELETE /api/file-agent/tasks/{id}` с `{ "confirmed": true }` → 204. Удаление активной задачи → 409. Проверки browser origin действуют для обоих методов.
- Существующая SQLite schema не перестраивается: cancellation/history flags сохраняются в JSON parameters. Внутренний terminal status остановленной задачи — `failed`, публичный — `cancelled`; выполняющая остановку задача возвращает `stopping`.

## Воспроизводимость

- **Re-run Task**: новое выполнение цели той же моделью и с сохранёнными параметрами в чистой копии того же commit. LLM-результат может отличаться.
- **Replay patch**: применение сохранённых точных изменений на новый snapshot без LLM, с повторными проверками. Private base bundle позволяет replay/rerun после удаления workspace или перемещения source refs.
- История SQLite содержит цель, модель, base SHA, параметры, реальные tool outcomes, прочитанные файлы, изменения, validation и usage; private metadata содержит hashes артефактов.
- После restart незавершённые задачи получают `failed`, а не фиктивный `completed`; их можно повторить.

## API и live smoke

База API: `/api/file-agent`. `POST /tasks` принимает `{ "prompt": "...", "model": "deepseek-flash" }`; `GET /tasks` — история; `GET /tasks/{id}` — состояние; `GET /tasks/{id}/events` — SSE из сохранённого журнала (Last-Event-ID поддерживается). UI использует bounded polling. `/diff`, `/file?path=...` и `/patch` — просмотр; POST `/rerun`, `/replay`, `/discard`, `/apply` — lifecycle. POST требует JSON и проверяет browser origin. Apply требует `{ "confirmed": true, "artifact_sha256": "..." }`, discard — `{ "confirmed": true }`.

```bash
# Явный платный live запуск трёх целей + точный replay каждого patch:
python3 scripts/day34_smoke.py --live --base http://127.0.0.1:3010
```

Скрипт сохраняет публичные JSON и redacted diff в `/tmp/opencode/day34-demos`; source apply/push не вызывает. Точные приватные артефакты остаются в persistent Docker volume.
